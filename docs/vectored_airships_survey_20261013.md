# Kelluu 와 HyLight: 벡터 추력 비행선과 가족 클래스 (2026-10-13)

사용자의 호기심 요청. 기체 제작 계획이 없어 검증할 수 없으므로 현 계획 (upstream_plan_20261013.md) 에는 반영하지 않는다. 기록만 남긴다.

## 2. 렌치 구조

우리 포드: 좌우 (0, ±b, 0) 에 1 축 틸트. 힘 F_i = T_i (cos θ_i, 0, −sin θ_i). 섬기는 축 4 개: 추력 x·z, 요 (x 차동), 롤 (z 차동).
피치와 횡력은 없다 (포드가 무게중심 종방향 위치에 있다는 가정).

**Kelluu — 후미 짐벌 하나, 위치 (−L, 0, 0), 힘 F = (Fx, Fy, Fz):**

    τ = r × F = (0, L·Fz, −L·Fy)

액추에이터 3 (T, 틸트, 팬) → 렌치 랭크 3. (Fz, 피치) 와 (Fy, 요) 가 쌍으로 묶여 따로 못 준다. 토크 권한 ∝ T: 추력 0 에서는 요·피치 권한이 없다.
PX4 로 보면 조종면 대신 벡터링을 쓰는 고정익에 가깝다: 토크 (피치·요) 와 추력 x 를 섬기고 추력 y·z 는 미배분으로 보고. 선형화 (작은 각,
T > 0) 하면 upstream 의 Custom (9) 으로 오늘도 표현된다: 팬 서보 → 요 토크, 틸트 서보 → 피치 토크 + 추력 z, 모터 → 추력 x. 비선형
(τ = L·T·sin) 과 짐벌 슬루·한계만 클래스가 더해 줄 수 있다. 고도는 피치로 날거나 (순항), 정지 시에는 Fz 로 — 제어기 설계가 어려운 쪽이지 배분기가 아니다.

**HyLight — 기수 (+Lf, 0, 0) 와 꼬리 (−Lr, 0, 0) 짐벌:**

    Fx = Fxf + Fxr,  Fy = Fyf + Fyr,  Fz = Fzf + Fzr
    τ_pitch = −Lf·Fzf + Lr·Fzr,  τ_yaw = Lf·Fyf − Lr·Fyr,  τ_roll = 0 (중심선)

액추에이터 6 → 렌치 랭크 5 (x, y, z, 피치, 요). 롤만 수동 (진자 안정). 힘 성분 → 렌치는 **선형** 이다 (5×6 행렬):

    Fyf = (τ_yaw + Lr·Fy)/(Lf+Lr),  Fyr = (Lf·Fy − τ_yaw)/(Lf+Lr)
    Fzf = (Lr·Fz − τ_pitch)/(Lf+Lr), Fzr = (Lf·Fz + τ_pitch)/(Lf+Lr)

영공간 하나 = Fx 의 앞뒤 분배 (짐벌 각을 줄이는 데 쓴다). 비선형은 포드 안에서만: 힘 벡터 → (T, 틸트, 팬), 비가역 프롭이면 우리 조향 밴드의
3 차원판 (원뿔). 정지 비행에서 횡력과 피치를 따로 주므로 검사 호버에 맞는 완전 구동 기체다.

## 3. 가족 클래스로 품을 수 있나

- **HyLight: 그렇다, 포드 모델의 확장으로.** 필요한 둘: (a) 포드 위치 (지금은 없다; 렌치가 정규화되어 있고 모멘트 암 파라미터가 없다),
  (b) 두 번째 축 (팬) 과 3 차원 조향. 그러면 podWrench 의 평균/차 대신 기하 행렬이 되고, 포드가 무게중심 종방향에 없을 때 피치가 생긴다.
  우리 클래스 = 이 일반형에서 위치 (0, ±b, 0), 틸트만인 경우. 요 루프와 뒤의 고도·위치 루프는 렌치 설정값을 내므로 달라지지 않는다.
- **Kelluu: 위 일반형의 포드 하나 퇴화 경우.** 랭크 3 이라 어느 설정값을 섬길지 (자세 우선) 정해야 하고, 그 선택은 제어기 (고도를 피치로
  나는가, Fz 로 나는가) 와 함께 간다. 배분기만 보면 작다; 기체는 Custom 으로도 오늘 뜬다.
- **지금 가족에 남기는 설계 메모 하나.** 포드에 위치를 주면 토크 단위가 정규화 (차동의 반) 에서 기하 (N·m 비례) 로 바뀌어 게인이 다시 매겨진다.
  앞뒤 스테이션을 언젠가 품을 생각이면 그 전환은 조종면 라운드 전후에 한 번에 하는 것이 싸다. 결정은 그 기체가 있을 때.
- **PX4 기존 클래스로는?** 틸트로터 VTOL (3) 은 틸트를 렌치에서 풀지 않고 VTOL 전환 논리가 스케줄한다. Custom (9) 은 선형이라 T > 0
  의 작은 각에서만 맞다. 두 기체 모두 "렌치에서 추력 벡터를 푸는" 우리 가족의 일이다.

## 4. 검증 불가

두 기체 모두 제작 계획이 없다. 이 메모는 가족 클래스의 일반화 방향 (위치 + 2 축 포드) 을 적어 둔 것이고, 코드·계획 변경 없음.
